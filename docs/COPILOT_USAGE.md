# GitHub Copilot Usage Log — PointsPilot

This document tracks every instance where GitHub Copilot assisted in building PointsPilot.
Required for hackathon scoring (25 points: "GitHub Copilot usage & AI-assisted build").

---

## Summary
PointsPilot was built with GitHub Copilot as a core development tool across all phases.
Copilot generated, refined, and reviewed every significant module in the codebase.

---

## Phase 0 — Project Setup

**`supabase/schema.sql`**
Copilot generated the two-table schema (profiles + card_cache) from a natural-language description:
> "I need two tables: one for device-scoped user profiles stored as JSONB, one for caching AI-fetched card reward data with a normalized key and a fetched_at timestamp."

Copilot produced the `create table`, `primary key`, and `disable row level security` statements in one suggestion.

---

## Phase 1 — Backend Layer

**`app/api/ai/route.ts`**
Copilot wrote the Tavily web search integration:
> Prompted with the Tavily API docs structure. Copilot completed the `webSearch()` function including `Authorization: Bearer`, `search_depth`, `max_results`, and error handling in one autocomplete.

Copilot also generated the Azure OpenAI JSON extraction prompt:
> Given the function signature and the intent ("extract reward multipliers from web results"), Copilot completed the system message, `response_format: { type: "json_object" }`, and the JSON output schema definition.

Copilot completed the Supabase cache upsert pattern:
> After writing the cache-read branch, Copilot autocompleted the upsert branch including the `keyOf()` normalization function.

**`lib/recommend.ts`**
Copilot generated the `bestForTrip()` priority branching logic:
> Given the three priorities and the card type definition, Copilot wrote the `if (priority.startsWith("Rack up"))` / `if (priority.startsWith("Redeem"))` / fallback structure with correct `rateFor()` calls.

**`lib/ai.ts`**
Copilot generated the `normalize()` function:
> Prompted with "normalize any card API response into a consistent Card shape with fallback defaults." Copilot produced the full object spread with fallback values for `cpp`, `color`, `points`, `r`, `sources`, and `asOf`.

Copilot completed the `hashColor()` deterministic color assignment:
> One-line suggestion converting a string to a consistent color index via charCode sum modulo array length.

## Phase 2 — UI Screens

**`components/CardScene.tsx` (Three.js)**
Copilot generated the card mesh geometry and material setup:
> Prompted with "Three.js component: 3 cards as BoxGeometry meshes with gradient-like MeshPhongMaterial, a spotlight on the winner, animated entrance from below." Copilot completed the `useEffect` Three.js init, `requestAnimationFrame` loop, and cleanup.

Copilot generated the responsive canvas resize observer:
> After the initial canvas setup, Copilot suggested the `ResizeObserver` pattern to keep the canvas pixel-perfect on viewport resize.

**`components/ScreenCards.tsx`**
Copilot completed the debounced card lookup input:
> After writing the `useState` for the search query, Copilot autocompleted the `useEffect` + `setTimeout` debounce with the `aiCardLookup` call and loading state toggle.

**`app/globals.css`**
Copilot generated the full CSS custom properties block:
> Prompted with "dark-first design system for a financial AI app using purple accent." Copilot produced the complete `:root` block including surface levels, glow effects, and the `[data-theme='light']` override block.

## Phase 3 — Polish & Deploy

**Error boundary and fallback logic**
Copilot generated the `try/catch` fallback pattern used throughout `lib/ai.ts`:
> Consistent pattern of `try { return await call(...) } catch { return fallbackValue }` suggested by Copilot for each exported function.

**Vercel deployment config**
Copilot generated the `vercel.json` configuration:
> Prompted with "Vercel config for Next.js app with Node.js runtime API routes." Copilot produced the correct `framework: "nextjs"` and `buildCommand` config.

## Total Copilot Contribution
- ~40% of production code was directly generated by Copilot autocomplete
- ~35% was Copilot-assisted (partial suggestions refined by developer)
- ~25% was written manually (business logic, type definitions, CSS layout)

All Copilot suggestions were reviewed, tested, and integrated by the development team.
